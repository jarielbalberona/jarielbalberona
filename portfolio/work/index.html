Featured project

Dumadine

Multi-tenant cafe operating system in early beta, built to run real workflows end-to-end instead of stopping at customer ordering.

dumadine.com

Scope

Customer ordering, merchant dashboard, POS flow, kitchen display, menu management, inventory behavior, and supporting system structure across frontend, backend, and deployment.

Why it matters

This is the kind of product that exposes whether the engineering can survive contact with operations. Ordering is easy to demo. Operational edge cases are where systems get expensive.

Working model

Built in close contact with a local cafe environment in the Philippines, which keeps requirements grounded and removes a lot of fake-product thinking.

Publicly shareable shape

What is visible in the system

  • QR customer ordering with real-time status updates
  • Merchant dashboard, POS, shifts, and cash-drawer flows
  • Kitchen display system with live ticket updates
  • Menu structure for items, modifiers, variants, and templates
  • Inventory support for recipes, stock, suppliers, and sales-linked decrements
  • Loyalty support for points and stamps
Technical shape

Current stack and engineering concerns

TypeScript, React, Node.js, Express, PostgreSQL, Drizzle, WebSockets, Docker, Terraform, and AWS-level deployment patterns.

The stack itself is not the interesting part. The interesting part is keeping the system modular enough to evolve while it is also being shaped by real operating feedback.

Why only one project right now

Depth is more useful than inventory.
